# KeyTao Review

用于把“查词/加词”从普通编码建议升级为带证据的审词流程。

## 使用原则

- 加词前优先调用 `keytao_prepare_reviewed_add`，不要只用默认 `keytao_encode`。
- 若 `keytao_prepare_reviewed_add` 返回 `pronunciationUnresolved=true`，只能向用户说明其 `message`；禁止回退 `keytao_encode`、展示默认码/候选码、建立确认或把该词放入多词批次。即使审词工具失败也不能用逐字默认音冒充整词结论。
- 工具会从汉典、萌典、百度百科、维基百科、汉语辞典等来源抽取拼音证据。
- 权威页未抓到时，先识别完整词语是地名、人名、品牌、作品或术语等哪类实体，再用高置信实体语境纠正多音字；例如地名中的多音字不能沿用逐字默认音。语境判断低置信、拼音音节数不符或无法映射键道音码时，必须回退并交给管理员，禁止臆造读音。
- 加词预审、提交审核和网页复审均遵循普通话标准读音，优先级为权威 > 含义及逐字读音已校验的语义读音 > 高置信实体语境 > 百科实体全称语境 > 默认音。语义或 LLM 读音可选候选组。词中有多音字时，仅凭语义选音的条目保持封存，交管理员复核。无权威整词页且逐字单音时，`semantic_context_common_word=PASS` 要求查询完成、逐字读音合法、具体含义置信度 ≥ 0.75，并满足整词 jieba ≥ 10，或逐字 jieba ≥ 1000 且模型确认常用或透明。整词词典命中不能作为此通道依据。`contextPronunciation.correctedDefault=true` 时使用纠正后的 `pronunciations/codes`。
- 自动审核使用分层证据：优先采用汉典、辞典、百科等可核验来源；若暂未抓到专门页面，常见现代汉语词、成熟术语或大众明确知晓的实体，也可用“本喵语言常识 + 常用词/实体信号”作为依据。
- 语言常识不能替代编码验证。指定编码属于另一合法候选组时，可按该组读音提交并封存。链外编码须按已审读音核验，未能核验时封存，确认有编码冲突才拒绝。
- 多个真实读音会全部展示，用户可以选择其中一个或多个编码。
- 展示各已审读音的合法编码并标明飞键。所有入码位置优先 `zhe → f`、`che/chu → j`，保留备用链。
- 多词批次按最严格条目聚合：任一词预审为“需管理员审核”，整批都不得自动通过；编码候选链正确不能覆盖词义、来源或常用度证据缺口。
- 删除项不能自动通过；“删除原位 + 创建同词新编码”的调码可按调码审核。
- 调码如果把某词排到另一个同编码词前面，必须比较常用度；语料、搜索、词典、百科信号一致时才自动通过。
- 更常用/更正确的判断要保守：证据不足或有反向信号时提交给管理员，不要强行自动通过。
- `CSS` / `CSSSingle`（声笔笔/声笔笔单字）不是普通 Phrase 的读音+形码候选链；不能用通用双拼或 `f+ao` 这类声韵猜测判错。声笔笔条目按短码表事实、同码链优先级、词频和结构对齐审查。
- “需管理员审核”不等于“不可提交”：只有编码/结构硬冲突、重复写入或后端校验失败才阻止提交；证据不足、歧义、纯删除可提交，直接说明“可提交，但需管理员审核”，不要描述“提交后等待”之类的过程。

## 工具

- `keytao_prepare_reviewed_add(word)`：返回读音来源、候选编码占位、推荐位置和自动审核资格；用户平台身份由执行器只读注入，不属于模型参数。
- `keytao_audit_draft_items(items)`：对草稿条目进行自动审核预判，返回 pass 或 needs_admin。
- 批量复审的 `aiReview.items[].reviewRecord.source=bot-lookup-transient` 表示仅因查询暂时失败而封存。Next 跳过「校验」摘要，留待复审。
